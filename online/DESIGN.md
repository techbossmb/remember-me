# remember-me — online mode design

Companion to DESIGN.md. Supersedes DESIGN.md's "Rejected: hosted raw logs" and the local-only parts of "Deployment".

## Decisions (2026-11-15)
- **Why now:** in the Claude app, memory on the user's Mac means the Mac must be awake with the app open; Python must be installed; the plugin is a settings step; the map link only works on that Mac; and nothing enforces separation between projects. A hosted service fixes all five. Grep over the network isn't a concern after all: the tools run where the memory is, and the assistant only sees results.
- **One set of tools, two places memory can live.** Every assistant sees the same `remember_*` tools. Offline = the plugin's local server + `~/.remember`. Online = the same tools over MCP's HTTP transport (FastAPI on FastAPI Cloud), memory in Neon Postgres, added to Claude as a connector by URL.
- **Storage interface** (`remember/store.py`): everything reads/writes file-like paths (`log/<p>/<s>.md`, `maps/<p>/events.jsonl`, …). `FileStore` = today's files; `PgStore` = the same paths as rows in one table, every query scoped by user id, advisory locks for concurrent writers. Same layout both ways, so export = a zip that works offline, and maps move between modes unchanged. A golden test (`tests/golden.py`) runs every CLI/MCP path and passes identically on both backends.
- **The user's own assistant still builds the map**, on their plan. The server stores and serves, never calls a model: hosting stays near-free and open sign-up is low-risk (abuse costs storage, not AI spend).
- **No sync between offline and online at first;** moving is export/import. Sync is cheap later because the log only grows, message ids are content-based, and map changes are appended events (merge ≈ union sorted by time).
- **Sign-in:** open sign-up from day one, as simple as possible: adding the connector sends the user to the auth provider ("Continue with Google"), and the first sign-in creates the account. The service is an OAuth resource server: it publishes protected-resource metadata, answers 401 pointing at it, verifies provider JWTs, and uses the token subject (namespaced by issuer) as the user id. Provider TBD; it must support how Claude registers clients (CIMD and/or DCR; DCR is deprecated in the 2026-07-28 MCP spec). Candidates with explicit MCP support: WorkOS AuthKit, Clerk, Auth0, Stytch.
- **Online v1 = tools only.** No hooks: every assistant saves at pauses with `remember_log`. Local-only tools (viewer, file import, Claude Code session ingest) are hidden online. Projects must be named explicitly online.
- **Privacy stance (user, 2026-11-15):** industry norm is disk/DB encryption + tightly controlled access, not per-user encryption of content; we follow that. What matters: very few people can read the DB (access logged), conversation text never goes into app logs or error reports, delete really deletes (and say how long backups keep it), an honest policy (we can technically read it, we don't, never train on it). Full encryption of content stays an option for a stronger statement later. Offline stays as the trust escape hatch while remember-me is small; decide its long-term future from usage.
- **Isolation, current behavior:** offline, any chat can read any project (convention, not enforcement). Online, one user can never see another's memory; between one user's projects it's still the assistant naming the project.
- **Status (2026-11-20):** deployed at https://remember-me.fastapicloud.dev (FastAPI Cloud us-east-1, Neon us-east-1, WorkOS AuthKit staging), working as a Claude connector end to end. Live map at /map with browser sign-in (same WorkOS account, so the same memory); forced Postgres row-level security on top of per-user filtering. Known limits: tool calls serialized per process, each log file one growing row. Before inviting others: rotate the WorkOS key and Neon password, WorkOS production with an own Google OAuth client, a privacy page.

## Switching between online and offline (2026-11-20)
- **One set of tools, a mode inside the local server.** On a computer with the plugin, `remember_mode` switches where memory lives. Online mode passes every memory tool call through to the account (same answers as the connector); offline mode uses `~/.remember`. Phone and web are always online (connector).
- **A project lives in one place at a time, so nothing ever merges.** Going offline downloads projects and *holds* them: online they become read-only (writes refused with a clear message; the map shows "offline on <computer>", edits disabled), or are removed from the cloud if the user chose that. Going online uploads the held projects (replacing the online copy), releases the holds, and sets the computer's copies aside under `backups/` so stale copies never look like conflicts later. A project that exists in both places without a hold is a conflict: nothing moves until the user picks (`replace=[…]`).
- **The two meanings of "go offline" are both supported,** asked the first time: away for a while (keep a read-only online copy) vs. "I don't want it in the cloud" (remove it).
- **Computers sign in with a device code,** like `fastapi login`: the assistant shows a link + code, the user allows it on a signed-in page, the computer gets a long-lived token (stored hashed server-side, in `~/.remember/config.json` locally).
- **Map while offline:** the local viewer on that computer; the online map shows the held snapshot read-only, or nothing if removed.
- **Prepared for real merging later:** every map event now carries a globally unique `eid`. Two-way merge (writing the same project in both places at once) is deferred until someone needs it; it also needs thread-id remapping.
- **Not yet in online mode on a computer:** importing a claude.ai export or Claude Code sessions (go offline, import, go back online); Claude Code hooks don't capture in online mode (the assistant saves through the tools).
- Tests: `online/test_sync.py` runs a computer's local server against a running service: device sign-in, conflict refusal, pass-through, offline with read-only online copy (phone write refused, map marked), offline edits uploaded on return, remove-from-cloud and restore.
